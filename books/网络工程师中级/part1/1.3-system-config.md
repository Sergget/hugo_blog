# 1.3 系统配置与性能评价 📊

## 1.3.1 系统构架模式 🏗️

在网络系统设计中，常见的两种架构模式对比：

* **C/S (Client/Server)**：客户端需安装专用软件。
    * **优点**：交互性强、响应快、安全性较高、协议私有。
    * **缺点**：维护成本高（需更新每个客户端）、跨平台性差。
* **B/S (Browser/Server)**：客户端使用通用浏览器。
    * **优点**：分布性强、维护方便（仅需升级服务器）、跨平台好。
    * **缺点**：响应速度受限于浏览器和网络、安全性较难控制。

## 1.3.2 RAID 技术与高可用性 💾

RAID（独立磁盘冗余阵列）用于提升存储性能和可靠性。

| RAID 级别 | 核心技术 | 磁盘利用率 | 冗余/容错能力 |
| :--- | :--- | :--- | :--- |
| **RAID 0** | 条带化 (Striping) | $100\%$ | 无冗余，坏一块数据全丢 |
| **RAID 1** | 镜像 (Mirroring) | $50\%$ | 允许坏一半磁盘（两两配对） |
| **RAID 5** | 分布式奇偶校验 | $(n-1)/n$ | 允许坏 **1** 块磁盘；至少需 3 块 |
| **RAID 6** | 双重校验 | $(n-2)/n$ | 允许坏 **2** 块磁盘 |
| **RAID 10** | 镜像+条带化 | $50\%$ | 兼顾性能与安全 |


## 1.3.3 系统可靠性模型 📈

### 1. 串并联计算公式
* **串联系统**：$R_{total} = R_1 \times R_2 \times \dots \times R_n$。
* **并联系统**：$R_{total} = 1 - (1 - R_1) \times (1 - R_2) \times \dots \times (1 - R_n)$。

### 2. 可用性指标
* **MTBF (平均无故障时间)**：越**大**越好。
* **MTTR (平均修复时间)**：越**小**越好。
* **可用性 (Availability)**：$A = \frac{MTBF}{MTBF + MTTR}$。
